## 四、当前卡点(未解决):GenerateMotionPlanService 仍 FAILED
原因已定位到**姿态(位姿)约束**这一层:
- 工具路径每个点要求「位置 + 姿态」同时满足,而 eco65 **完整位姿 IK = 0/47**。
- 已排除 sand_tcp 工具偏移因素:去掉工具偏移、只让 **Link6 本体**去够,仍是 0/47。
- 已做底座摆放初扫(纯平移,Xb∈[-0.62,-0.26]、Zb∈[0.55,1.05],table 系):
  姿态可达率**全部 0%**。
- 疑点一:求解器对姿态约束是否假阴性(需地真验证);
  疑点二:eco65 在当前底座朝向 / 工具安装下,真达不到沿 mesh 法线(~32° 倾角)的姿态。

## 五、下一步计划
1. **先做 IK 求解器地真验证**——用几个已知可达的关节配置反解其位姿,
   确认 `pose_ik` 本身没 bug,排除「求解器假阴性」。这是当前最大疑点。
2. 若求解器正常 → 说明 eco65 在现底座朝向 / 工具安装下真达不到工具姿态,两条路:
   a. 重新设计 `workcell.xacro` 里 `sand_tcp_joint` 的安装 RPY
      (现为继承 hc10 的 `rpy=(0, -90°, -135°)`),让磨头轴线更自然地压向工件;
   b. 或给底座**加旋转**(俯仰/偏航)再搜可达摆放——注意:纯平移不改变「相对 baselink
      的姿态需求」,只有让底座旋转才能真正降低姿态难度。
3. 找到 eco65 能「带姿态打磨」的布局后,改 `urdf/workcell.xacro` 的 `table_to_base`
   → `scripts/restart_demo.sh` 重启 → 在 RViz 重新框选 ROI + 设起点生成工具路径
   → 验证 GenerateMotionPlan 通过 → 走到执行打磨动作,闭环整个流程。
4. 闭环后(非紧急):通过宿主 Humble 环境连接真实 eco65,把仿真流程迁移到真机。
